# VaultBranch 1.0.11 performance and validation

Version/tag: [1.0.11](https://github.com/crli-idea/VaultBranch/tree/1.0.11). Baseline: [1.0.10 / f06938d46e6bdda766dfd03de66b9a5aca5a719a](https://github.com/crli-idea/VaultBranch/tree/1.0.10). Tested runtime source: [63a2904e94d13b70fc903b74676d4c0033fabf78](https://github.com/crli-idea/VaultBranch/commit/63a2904e94d13b70fc903b74676d4c0033fabf78). Subsequent release commits change documentation only. [Raw samples](https://github.com/crli-idea/VaultBranch/blob/1.0.11/docs/performance/1.0.11-samples.json).

This release updates current repository links and the build banner to crli-idea/VaultBranch, adds concise installation, usage and capability disclosures, and replaces the SVG toolbar relational CSS selector with an explicit scoped class. Release provenance is generated and verified under the current repository and its release workflow. Git operations and clipboard behavior are unchanged. No dependency or speedup claim.

## Environment and methods

platform: win32 10.0.19045; node: v24.22.1; electron: 43.8.4; git: git version 2.50.0.windows.1; obsidian: 1.15.1; installer: 1.15.0; plugin: 1.0.11. Official baseline files were downloaded and SHA-256 verified. Both builds were tested sequentially in one complete release-check invocation, using an isolated temporary repository in note_test. Existing test-vault Git metadata, settings and notes are preserved and restored. The application is Obsidian 1.15.1, so these numbers should not be directly compared with historical runs on 1.15.0.

Startup: one warm-up plus five measured plugin reloads with warm OS/V8 caches, views closed and openOnStartup=false. CPU sampling, logging, highlighting, autosave, folding and table compatibility off. First sidebar and first diff include Git reads/editor setup and are reported separately; full application cold start and physical paint are not measured. Dataset scale is in the raw startup reports.

Switching: 100 Staged and 100 Changed files; small Markdown → 1.6 MB JSON → small JSON → 1.28 MB Markdown, at least three directory levels and duplicate basenames. Eight warm-up clicks, then 20 trusted native GUI clicks per area/build. CPU sampling and timing logging on; autosave, highlighting and table compatibility off. domReadyMs requires the target title, text and controls together; completedMs also includes subsequent verification. Input delay, queue and frame callbacks remain separate in raw records.

Changed editing: one warm-up plus five measured rounds for each of four fixtures and three operations (60 trusted samples/build). CPU sampling, logging, highlighting, autosave, folding and table compatibility off. Event-to-document and synchronous dispatch are separate. Saving and fixture restoration are outside timers; index, drafts and cleanup are checked. Frame callbacks do not establish physical paint.

Both builds were tested in one complete release-check run.

## Switching variation follow-up

The complete run above had higher candidate switching medians. A second isolated run reversed the order (1.0.11 first, then 1.0.10), using the same fixture and native-click/CPU-profiling scripts. Git subprocess durations increased substantially for both builds; the earlier relative slowdown did not repeat. These observations do not establish a code-caused regression or a speedup, and are retained separately rather than pooled. Units: ms, median [min-max].

| Reverse-order follow-up / page ready | 1.0.10 | 1.0.11 | Samples/build |
| --- | --- | --- | --- |
| staged | 555.4 [254.3-911.3] | 397.5 [234.6-703.8] | 20 |
| unstaged | 363.5 [151.0-591.3] | 220.2 [104.0-412.9] | 20 |

Reproduce by installing each build in the stated order in note_test, running staged-switch-ui.js followed by profile-switch-ui.js for each, and restoring settings and plugin files afterward. Both runs check trusted clicks, correct content and unchanged index. Raw follow-up samples are included in the linked JSON.

## Reproduction

Use official 1.0.10 main.js, manifest.json and styles.css as the baseline directory. Enable VaultBranch only in note_test, preserve existing settings/Git metadata, ensure there are no unsaved drafts, and keep the test window available for trusted input. Run:

```sh
npm run release:check -- --obsidian-cli <Obsidian CLI> --baseline-build <official 1.0.10 assets> --output-dir <outside-vault results>
```

The runner performs validation, all automated tests, build, both builds' three performance probes and all UI suites. Benchmark and native UI scripts are under scripts/benchmark-startup.js and tests/manual/.
