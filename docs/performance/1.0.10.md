# VaultBranch 1.0.10 performance and validation

Version/tag: [1.0.10](https://github.com/li-cr/VaultBranch/tree/1.0.10). Baseline: [1.0.9 / f7c46a4437368afb36754177ef87dba8be160af0](https://github.com/li-cr/VaultBranch/tree/1.0.9). Tested runtime source: [84b6f394273b28ab07a58ff44be8cd793610485d](https://github.com/li-cr/VaultBranch/commit/84b6f394273b28ab07a58ff44be8cd793610485d). Subsequent release commits change documentation only. [Raw samples](https://github.com/li-cr/VaultBranch/blob/1.0.10/docs/performance/1.0.10-samples.json).

This release adds padded local dates (YYYY/MM/DD, plus 24-hour time in file history), four resizable history columns with persisted widths, and full commit hash copying. Resizing updates CSS without replacing rows or reading Git, and saves once on pointer release. Neighboring columns retain minimum widths; narrow panes scroll horizontally. Double-click or Home restores fluid defaults. Copy buttons do not select/open their parent commit. No new dependency or speedup claim.

## Environment and methods

platform: win32 10.0.19045; node: v24.22.1; electron: 43.8.4; git: git version 2.50.0.windows.1; obsidian: 1.15.1; installer: 1.15.0; plugin: 1.0.10. Official baseline files were downloaded and SHA-256 verified. Both builds were tested sequentially in one complete release-check invocation, using an isolated temporary repository in note_test. Existing test-vault Git metadata, settings and notes are preserved and restored. The application is Obsidian 1.15.1, so these numbers should not be directly compared with historical runs on 1.15.0.

Startup: one warm-up plus five measured plugin reloads with warm OS/V8 caches, views closed and openOnStartup=false. CPU sampling, logging, highlighting, autosave, folding and table compatibility off. First sidebar and first diff include Git reads/editor setup and are reported separately; full application cold start and physical paint are not measured. Dataset scale is in the raw startup reports.

Switching: 100 Staged and 100 Changed files; small Markdown → 1.6 MB JSON → small JSON → 1.28 MB Markdown, at least three directory levels and duplicate basenames. Eight warm-up clicks, then 20 trusted native GUI clicks per area/build. CPU sampling and timing logging on; autosave, highlighting and table compatibility off. domReadyMs requires the target title, text and controls together; completedMs also includes subsequent verification. Input delay, queue and frame callbacks remain separate in raw records.

Changed editing: one warm-up plus five measured rounds for each of four fixtures and three operations (60 trusted samples/build). CPU sampling, logging, highlighting, autosave, folding and table compatibility off. Event-to-document and synchronous dispatch are separate. Saving and fixture restoration are outside timers; index, drafts and cleanup are checked. Frame callbacks do not establish physical paint.

Only the final runtime build and successful complete release-check run are reported below. Earlier runs were discarded after test-harness failures: a copy Notice overlapped the next suite's button, a native-input sample lost focus, and an explorer fixture was outside its virtualized visible range. The harness now removes its own copy Notice, focuses each native-input sample, and reveals the explorer fixture before querying it. Their timing results are excluded.

## Correctness

160 automated tests and 1012 Obsidian UI assertions passed in one complete run. New unit tests cover local date padding and time, invalid saved widths, neighboring-column limits and snapshot immutability. The native table suite verifies four trusted drags, exact boundary movement, heading/body alignment, persisted/reopened widths, keyboard adjustment, reset synchronization across two views, narrow-pane scrolling, full-hash clipboard API delivery, keyboard row selection and unchanged index bytes. Clipboard delivery is observed through a scoped writeText stub, preserving the user's clipboard. Existing Stash, first-Push, Changed/Staged, conflict, SVG/image, file history and optional table suites also pass. Final sessions, pending reads and runtime/console errors: zero.

During four native column drags: zero Git history/detail reads, zero row replacements, zero settings writes during movement, and one settings write per release. These are deterministic operation counts, not an end-to-end speedup comparison; the previous release has no equivalent resize feature.

## Reproduction

Use official 1.0.9 main.js, manifest.json and styles.css as the baseline directory. Enable VaultBranch only in note_test, preserve existing settings/Git metadata, ensure there are no unsaved drafts, and keep the test window available for trusted input. Run:

```sh
npm run release:check -- --obsidian-cli <Obsidian CLI> --baseline-build <official 1.0.9 assets> --output-dir <outside-vault results>
```

The runner performs validation, all automated tests, build, both builds' three performance probes and all UI suites. Benchmark and native UI scripts are under scripts/benchmark-startup.js and tests/manual/.
