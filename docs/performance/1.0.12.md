# VaultBranch 1.0.12 performance and validation

Version/tag: [1.0.12](https://github.com/crli-idea/VaultBranch/tree/1.0.12). Baseline: [1.0.11 / 9b811f4572fa62de70975fb3dbaefd155a579302](https://github.com/crli-idea/VaultBranch/tree/1.0.11). Tested runtime source: [c906a5d22c332c0717c26c49aa3b286a2308a1ec](https://github.com/crli-idea/VaultBranch/commit/c906a5d22c332c0717c26c49aa3b286a2308a1ec). Subsequent release commits update documentation only. [Raw samples](https://github.com/crli-idea/VaultBranch/blob/1.0.12/docs/performance/1.0.12-samples.json).

## Changes

- Restore displayed settings when a Git-busy guard rejects a change. Apply text preferences on Enter/blur, normalize numeric values visibly, and apply a completed Git path once.
- Disable unavailable graph toolbar/detail/menu actions while Git is busy or a merge/conflict is active; keep Fetch available during conflicts. Keep backend Git and draft guards.
- Add a zero-match graph search message without hiding graph rows, graph Up/Down/Home/End focus navigation, and sidebar tree navigation/expand/collapse keys.
- Synchronize conflict action tooltips/accessibility labels and add refresh to conflict error pages. Preserve result drafts and explicit save/stage behavior.
- Use a neutral Pull command name for both configured pull methods, translate diff autosave, and simplify settings descriptions.

This is a UI correctness release. No Git read or safety check was removed; no dependency was added. No general speedup claim.

## Environment and methods

platform: win32 10.0.19045; node: v24.22.1; electron: 43.8.4; git: git version 2.50.0.windows.1; obsidian: 1.15.1; installer: 1.15.0; plugin: 1.0.12. Official 1.0.11 baseline assets were SHA-256 checked against GitHub release digests. Both builds ran sequentially in one complete release-check invocation in note_test. Existing notes, the manual conflict fixture, Git metadata and settings were preserved and restored. Full application cold start and physical paint were not measured.

An earlier full attempt stopped at a native UI wait after the separate Settings window closed. The runner now restores vault focus between suites. That attempt is excluded from the results below; only the subsequent completed invocation is used.

Startup: one warm-up and five measured reloads with warm OS/V8 caches, views closed, openOnStartup=false. CPU sampling, logging, highlighting, autosave, folding and table compatibility off. First sidebar and first diff include their Git/editor work and are reported separately. Dataset scale is recorded in the raw startup reports.

Switching: 100 Staged and 100 Changed files; small Markdown → 1.6 MB JSON → small JSON → 1.28 MB Markdown, at least three directory levels and duplicate basenames. Eight warm-up clicks, then 20 trusted GUI clicks per area/build. CPU sampling and logging on; highlighting, autosave and table compatibility off. domReadyMs includes target title, content and controls; completedMs includes subsequent verification. Input delay, queue and frame callbacks are separate in raw records.

Editing: four file fixtures × three operations × five measured rounds after warm-up, 60 trusted input samples/build. CPU sampling, logging, highlighting, autosave, folding and table compatibility off. Event-to-document time and synchronous dispatch are separate; save and fixture restoration are outside timers. The index, drafts and cleanup are checked. Frame callbacks do not guarantee physical paint.

## Targeted settings result

For four successive Git-path text edits, the audit of 1.0.11 recorded four update callbacks (one per input). The fixed UI records zero while typing and one after Enter. This is a deterministic callback-count comparison, not elapsed-time or Git-process timing. Reproduce with tests/manual/ui-consistency.js; it uses real callbacks and settings effects, intercepts preference persistence, and restores settings. The separate timing-settings-ui.js verifies actual retention persistence and invalid-input rollback.

## Reproduction

Use official 1.0.11 main.js, manifest.json and styles.css as the baseline directory. Enable VaultBranch only in note_test, preserve settings and Git metadata, save drafts, and keep the test window available for trusted input. Run:

```sh
npm run release:check -- --obsidian-cli <Obsidian CLI> --baseline-build <official 1.0.11 assets> --output-dir <outside-vault results>
```

The runner validates, tests and builds, measures both versions' startup/switching/editing, then executes all UI suites. It is read-only with respect to remote Git services. Benchmark and UI scripts are under scripts/benchmark-startup.js and tests/manual/.
