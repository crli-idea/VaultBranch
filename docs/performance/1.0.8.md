Version/tag: [1.0.8](https://github.com/li-cr/VaultBranch/tree/1.0.8). Baseline: [1.0.7 / e7b50357f9aeb3189c3b330466e3af290e2ce7a9](https://github.com/li-cr/VaultBranch/tree/1.0.7). ## Scope

Replace the conflict textarea with a native CodeMirror MergeView: incoming/upstream read-only and an editable local merge result. Pane order is configurable. Previous/next follows real conflict blocks. Accept left/right follows displayed identity; accept both retains shared context once and keeps differing content in pane order. The result starts from Git's auto-merged working file, retaining automatic edits from both versions. Choices and manual edits remain drafts until explicit completion, which checks original working-file text and index stages before saving and staging.

Conflict block parsing, resolution state/undo, line-aware diff boundaries and editor lifecycle are separate modules. Ordinary Changed/Staged/history editor logic is unchanged. Status subprocesses now set GIT_OPTIONAL_LOCKS=0, preventing optional index-stat refresh writes from competing with explicit staging/resolution; live status reads and ordinary writer locks remain. Conflict completion also checks an optional index-stage signature. No new dependency is added. Conflict controls use Obsidian theme variables; change/selection colors use CodeMirror native light/dark defaults. Those defaults do not automatically match every third-party Obsidian palette. Whole-file deletion/binary conflicts retain external-tool fallbacks. This is a feature/correctness release, with no speedup claim.

## Environment and methods

platform: win32 10.0.19045; node: v24.22.1; electron: 43.8.4; git: git version 2.50.0.windows.1; obsidian: 1.15.0; installer: 1.15.0; plugin: 1.0.8. Baseline and candidate execute sequentially in one complete release-check invocation. Official baseline assets match GitHub release SHA-256 digests. Source/build hashes and synthetic raw samples are linked above.

Startup: one warm-up and five retained plugin reloads with warm OS/V8 caches, plugin views closed and openOnStartup=false. CPU sampling, timing logging, autosave, syntax highlighting, folding and table compatibility are off; automatic refresh remains at five seconds. loadPluginMs includes script evaluation, host lifecycle/settings and CSS; onloadMs measures the host load lifecycle portion. First sidebar and first diff are measured separately, including reads/editor setup. Full-application cold startup and physical paint are not measured. The local test vault uses an isolated temporary repository for this run; startup dataset details are recorded in startup.scale.

Switching: 100 Staged and 100 Changed files, small Markdown → large nested JSON → small nested JSON → large Markdown, with duplicate basenames and three directory levels. Each build uses eight warm-up clicks and 20 retained trusted native clicks per area. CPU sampling and timing logging are on; autosave, syntax highlighting and table compatibility are off. DOM readiness requires the target title, body and controls together; completedMs additionally includes Changed verification. Input delay, queue and frame callbacks are separate in raw samples. Frame callbacks do not establish physical paint.

Changed editing: one warm-up and five retained rounds per fixture/operation, 60 trusted character/Enter/Backspace samples per build. CPU sampling, logging, highlighting, autosave, table compatibility and folding are off. Event-to-document latency and synchronous dispatch are separate; saving/restoration is outside timers. Fixture index, drafts and undo are checked. Keep the test window focused during native input.

Four earlier attempts were discarded in full: one failed the focus/composition guard; one stopped at native image dragging; two encountered competing background index locks. Image input now uses CDP, matching event coordinates and an explicit hover; timing fixture setup suspends background refresh around direct index changes. When the lock issue repeated elsewhere, an isolated stale-stat probe confirmed that plain git status refreshed the on-disk index. Status now disables optional Git locks, and a real Git regression verifies index-byte preservation, live edit detection, normal writer-lock rejection and successful explicit staging. No measurements from interrupted attempts or the pre-fix runtime are reused; failure logs remain local.
