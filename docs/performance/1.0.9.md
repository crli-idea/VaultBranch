# VaultBranch 1.0.9 performance and validation

Version/tag: [1.0.9](https://github.com/li-cr/VaultBranch/tree/1.0.9). Baseline: [1.0.8 / 9e22aae94f1ced631b88b9a9820b2b2015667714](https://github.com/li-cr/VaultBranch/tree/1.0.8). Tested runtime source: [e7b02413d81d1f7a5232bf8cda1a2ab2f8310efa](https://github.com/li-cr/VaultBranch/commit/e7b02413d81d1f7a5232bf8cda1a2ab2f8310efa). Subsequent release commits change documentation only. [Raw samples](https://github.com/li-cr/VaultBranch/blob/1.0.9/docs/performance/1.0.9-samples.json).

This release adds folder stage/unstage, first Push target selection, confirmed Stash Drop, an explicit sidebar Pop label, and a compact graph tooltip without duplicate title/aria-label overlays. Existing Git validation, drafts, selected-stash hash lookup and non-force pushes remain. No new dependency or speedup claim.

## Environment and methods

platform: win32 10.0.19045; node: v24.22.1; electron: 43.8.4; git: git version 2.50.0.windows.1; obsidian: 1.15.1; installer: 1.15.0; plugin: 1.0.9. Official baseline files were downloaded and SHA-256 verified. Both builds were tested sequentially in one complete release-check invocation, using an isolated temporary repository in note_test. Existing test-vault Git metadata, settings and notes are preserved and restored. The application is Obsidian 1.15.1, so these numbers should not be directly compared with historical runs on 1.15.0.

Startup: one warm-up plus five measured plugin reloads with warm OS/V8 caches, views closed and openOnStartup=false. CPU sampling, logging, highlighting, autosave, folding and table compatibility off. First sidebar and first diff include Git reads/editor setup and are reported separately; full application cold start and physical paint are not measured. Dataset scale is in the raw startup reports.

Switching: 100 Staged and 100 Changed files; small Markdown → 1.6 MB JSON → small JSON → 1.28 MB Markdown, at least three directory levels and duplicate basenames. Eight warm-up clicks, then 20 trusted native GUI clicks per area/build. CPU sampling and timing logging on; autosave, highlighting and table compatibility off. domReadyMs requires the target title, text and controls together; completedMs also includes subsequent verification. Input delay, queue and frame callbacks remain separate in raw records.

Changed editing: one warm-up plus five measured rounds for each of four fixtures and three operations (60 trusted samples/build). CPU sampling, logging, highlighting, autosave, folding and table compatibility off. Event-to-document and synchronous dispatch are separate. Saving and fixture restoration are outside timers; index, drafts and cleanup are checked. Frame callbacks do not establish physical paint.

Earlier attempts were discarded: one automated harness fixture omitted the upstream required by the new first-Push routing; another run used the pre-tooltip build after the user supplied the screenshot. Their local results are not used below.

## Correctness

157 automated tests and 969 Obsidian UI assertions passed in one full run. The new native-click suite verifies collapsed/nested folder scope, unchanged adjacent folders, unstage, origin selection among multiple remotes, explicit destination branch/upstream, dirty-worktree preservation, visible Stash Pop and Drop, cancellation, selected content, hash-based removal after stash numbers shift, index-byte preservation, compact graph tooltips and accessible search descriptions. Git integration tests additionally cover unborn/detached branches, stale targets, rejected non-fast-forward pushes and repeated/stale Drop attempts. Existing conflict/editor/SVG/image/history/table suites also pass. Final sessions, pending reads and runtime/console errors: zero.

## Reproduction

Use official 1.0.8 main.js, manifest.json and styles.css as the baseline directory. Enable VaultBranch only in note_test, preserve existing settings/Git metadata, ensure there are no unsaved drafts, and keep the test window available for trusted input. Run:

```sh
npm run release:check -- --obsidian-cli <Obsidian CLI> --baseline-build <official 1.0.8 assets> --output-dir <outside-vault results>
```

The runner performs validation, all automated tests, build, both builds' three performance probes and all UI suites. Benchmark and native UI scripts are under scripts/benchmark-startup.js and tests/manual/.
